# Governance

## Project maintainers

Maintainers are responsible for reviewing contributions, protecting users,
maintaining project quality, and making release decisions. The repository owner
may add or remove maintainers as the project grows.

## Decision making

Small fixes can be merged after normal review. Changes that affect public
behavior, authentication, data storage, deployment, or the contributor
workflow should be discussed in an issue or pull request before implementation.

When consensus is not possible, the repository owner or designated maintainer
makes the final decision, documenting the reasoning in the relevant issue or
pull request.

## Contributions

All contributors work under the [Code of Conduct](./CODE_OF_CONDUCT.md).
Contributions are reviewed according to [CONTRIBUTING.md](./CONTRIBUTING.md).
Maintainers may request changes, reject unsafe changes, or close inactive
contributions with an explanation.

## Changes to governance

Proposed governance changes should be submitted as a pull request and explain
their effect on contributors and maintainers.
